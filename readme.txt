Codex 효율적인 사용법

1) 요청은 구체적으로 작성하기
- 원하는 결과물, 대상 파일/폴더, 제약사항(언어/프레임워크/스타일)을 한 번에 전달하세요.
- 예: "Unity NGO 서버 권위 이동 코드로 PlayerMovement.cs 수정하고, 변경 이유를 3줄로 설명해줘."

2) 작업 범위를 명확히 지정하기
- "이 폴더만", "이 파일들만"처럼 범위를 지정하면 불필요한 탐색이 줄어듭니다.
- 큰 프로젝트에서는 먼저 "구조 요약"을 요청한 뒤 세부 작업으로 들어가면 빠릅니다.

3) 완료 기준(Definition of Done) 제시하기
- 테스트/빌드/로그 확인 등 완료 조건을 명시하면 재작업이 줄어듭니다.
- 예: "수정 후 에디터 컴파일 에러 0, 핵심 함수 유닛 테스트 통과."

4) 한 번에 너무 많은 목표를 섞지 않기
- "설계"와 "구현"과 "배포"를 분리해 요청하면 정확도가 높아집니다.
- 권장 순서: 요구사항 정리 -> 설계안 -> 구현 -> 검증 -> 커밋 메시지.

5) 코드 스타일/규칙을 먼저 알려주기
- 네이밍 규칙, 아키텍처 패턴, 금지 라이브러리 등을 초기에 공유하세요.
- 기존 팀 규칙이 있으면 해당 규칙을 우선 적용하도록 요청하세요.

6) 변경 후 반드시 검증 루프 돌리기
- "무엇을 바꿨는지" + "왜 바꿨는지" + "어떻게 검증했는지"를 함께 받으세요.
- 필요하면 "실패 케이스 2개"를 같이 요청해 회귀를 줄이세요.

7) 반복 작업은 템플릿화하기
- 자주 쓰는 프롬프트를 템플릿으로 고정하면 품질과 속도가 안정됩니다.
- 예: "문제 재현 -> 원인 추정 3개 -> 최소 수정안 -> 테스트 명령 -> 리스크" 형식.

8) 대규모 변경은 단계별로 커밋하기
- 기능 단위로 쪼개면 리뷰와 롤백이 쉬워집니다.
- 각 단계마다 "변경 파일 목록"과 "영향 범위"를 확인하세요.

9) 모호하면 먼저 탐색 요청하기
- 바로 수정 지시보다 "관련 코드 위치/호출 경로부터 찾아줘"가 더 안전할 때가 많습니다.
- 특히 멀티플레이/네트워크 코드는 의존성이 크므로 탐색 단계가 중요합니다.

10) 최종 산출물 형식을 지정하기
- "요약 5줄", "체크리스트", "PR 본문 형식" 등 출력 형태를 지정하면 바로 활용 가능합니다.

빠른 요청 예시
- "E:\Unity\WoopRider에서 NGO 플레이어 스폰 흐름 찾아서 핵심 파일 3개와 호출 순서만 알려줘."
- "ServerRpc 입력 검증 로직 추가하고, 변경 파일/테스트 방법/리스크를 짧게 정리해줘."

권장 작업 사이클
1. 현재 상태 파악(구조/오류/로그)
2. 작은 단위 수정
3. 즉시 검증(컴파일/테스트)
4. 변경 요약 확인
5. 다음 단계 진행

이 문서는 실무에서 Codex와 협업할 때 시간을 줄이고 결과 품질을 높이기 위한 기본 가이드입니다.
